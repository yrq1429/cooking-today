## 1. 产品定位

**可发布的微信小程序产品**(非 demo、非纯自用工具),个人主体注册。

三个核心场景:

1. **每天吃什么**——AI 每日菜单推荐(带推荐理由)
2. **搜菜谱**——语义搜索 + 菜谱详情(做法)
3. **拍照打卡**——做完菜拍照记录,烹饪日历

**明确不做**(本期):

- 食材反查(拍照食材 → 告诉你怎么做)——已从范围中移除
- 社交内容流 / 社区——个人主体无法过社交类目,打卡内容仅自己可见 + 微信原生转发好友
- 账号密码体系——`wx.login()` + 云开发 openid 无感登录

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 小程序框架 | Taro 3 + React + TypeScript | Owner 6 年 React 经验直接复用;保留未来出 H5 的可能(不承诺双端) |
| 后端 | 微信云开发 CloudBase(云函数 + 云数据库 + 云存储) | 免运维、免域名备案、内置登录,个人开发者冷启动 ≈ ¥0 |
| 大模型(默认) | 智谱 GLM 全家桶:GLM-4-Flash(建库+线上兜底)、Embedding-3(语义搜索)、GLM-4V(V2 拍照识别) | Flash 档免费;一家覆盖 LLM/embedding/多模态;国内可直连 |
| 大模型(可选加强) | Moonshot KIMI API(kimi-k2)仅用于数据工厂「生成 Agent」 | 生成质量上限更高;⚠️ KIMI C 端订阅 ≠ API,需单独充值;Moonshot 无公开 embedding,不可替代智谱 |
| 语义搜索实现 | 向量存 recipes 表字段内,云函数内存算余弦相似度 | 几千条规模毫秒级,不引入独立向量数据库 |

模型可插拔:生成/校验/推荐各环节通过统一 LLM client 抽象,换模型不改流程。

## 4. 数据模型(云数据库)

### recipes(菜谱,工厂产出)

```js
{
  _id, name,                        // 菜名
  category,                         // 荤菜/素菜/汤/主食/凉菜/甜品...
  cuisine,                          // 川/粤/家常/湘...
  ingredients: [{ name, amount, unit }],   // 结构化食材
  steps: [{ order, text }],                // 分步做法
  taste_tags: [],                   // 辣/清淡/酸甜/咸鲜...
  scene_tags: [],                   // 快手菜/下饭菜/一人食/孩子爱吃/季节标签...
  difficulty,                       // 1-5
  time_minutes, servings,
  nutrition: {
    calories,                       // 千卡/份,估算值,界面标注"估算"
    note                            // 一句话营养特点,如"高蛋白偏清淡"
  },
  cover_image,                      // V1 统一插画占位;AI 生成封面为后期可选项
  embedding: [],                    // Embedding-3 向量,语义搜索用
  quality_score,                    // 工厂校验产出
  status,                           // published / draft
  created_at
}
```

索引:`category`、`status`、`taste_tags`(数组索引)。

### users(用户画像,推荐的燃料)

```js
{
  _openid, nick, avatar,            // 头像昵称走官方填写能力,用户愿意才填
  taste_profile: {
    likes: [], dislikes: [],
    spicy_level,                    // 0-3
    taboo: []                       // 忌口
  },                                // 首次进入 onboarding 收集
  stats: { checkin_count, streak }
}
```

### checkins(打卡记录)

```js
{
  _id, _openid,
  recipe_id,                        // 手动关联;V2 由 AI 识别自动回填
  photo,                            // 云存储 fileID
  date,                             // YYYY-MM-DD
  note,
  ai_comment,                       // 异步生成的一句点评,失败则不展示
  created_at
}
```

索引:`_openid + date` 组合索引。

## 5. 菜谱数据工厂(离线 multi-agent pipeline)

目标:**3000 道结构化、去重、质量可控的菜谱**,灌入云数据库。

```
规划 → 生成 → 校验 → 打标签 → embedding + 导出
plan.json → raw/ → validated/ → tagged/ → final.jsonl
```

1. **规划 Agent**:按「分类 × 菜系 × 场景」矩阵规划 3000 个不重复菜名(本地种子列表 + LLM 扩充 + 去重),保证库的多样性,避免全是番茄炒蛋变体
2. **生成 Agent**:每个菜名 → 固定 JSON schema 的结构化菜谱,并发限流(GLM-4-Flash 免费档约跑 2-3 天;可选充值 KIMI API 提速提质)
3. **校验 Agent**:双层——规则校验(JSON schema、食材量合理区间、步骤数、必填字段)+ LLM 质检员(检查"步骤出现食材表没有的食材"等硬伤)。不合格打回重生成,记录 quality_score
4. **标签 Agent**:口味/场景/季节标签,独立一步可单独重跑
5. **导出**:批量 embedding → JSON Lines → 云开发 CLI 导入

工程要求:**每步落盘、可断点续跑、质量分可追溯**;跑完输出质量报告(通过率、打回率、分类分布),人工抽检 20-30 道。

## 6. 场景设计

### 6.1 每日推荐(首页 tab)

每天 3 道推荐卡片(菜名/图/耗时/难度/推荐理由)。

```
规则筛选(云函数): 排除近 7 天打卡过的 → 按 taste_profile 过滤忌口/辣度
  → 季节加权、随机分层抽样 → 20 个候选
LLM 挑选: 候选摘要 → GLM → 返回 [{recipe_id, reason}]
  reason 须引用用户画像(如"你上周吃了 3 次辣的,今天换个清淡的…")
防幻觉校验: recipe_id 必须在候选集内 → 不在则重试 1 次
  → 仍失败兜底:规则排序 top3 + 模板理由
```

- 每天首次打开生成,**缓存当日结果**;「换一批」按钮重新走流程
- 「就做这道」跳菜谱详情;首次使用先走 onboarding 收集口味画像
- 推荐理由在界面标注「由 AI 生成」

### 6.2 搜菜谱(语义搜索)

- query → Embedding-3 → 与库内向量余弦相似度 top N → **混合排序:语义分 × 0.7 + quality_score × 0.3**
- **降级**:embedding API 故障 → 关键词匹配兜底,搜索永远可用
- 无关 query(如"怎么修电脑"):相似度低于阈值 →「没找到相关菜谱」+ 热门推荐
- 详情页:食材表 / 分步做法 / 营养估算(标注"估算")/ 耗时难度 + 「做完打卡」按钮

### 6.3 拍照打卡

- 两个入口:详情页「做完打卡」(自动关联菜谱);打卡 tab 直接拍(手动选菜谱)
- 流程:拍照/相册 → 压缩 → 上传云存储 → 写 checkins → **异步生成 ai_comment**(一句有趣点评)→ 日历更新
- 日历 tab:月历视图(有打卡的日期显示小图),点日期看卡片,展示连续打卡 streak
- 分享:打卡卡片转发好友(微信原生分享,V1 就做);朋友圈海报 V2
- **V2 预留**:拍照识别菜品自动关联菜谱(GLM-4V),`checkins.recipe_id` 已兼容识别后回填

## 7. 错误处理与费用保护

- 所有 LLM 调用:**超时 + 重试 1 次 + 降级兜底**(推荐→模板理由;ai_comment→预设文案或不展示;语义搜索→关键词匹配)
- LLM 输出一律过 JSON schema 校验
- 费用保护:云函数内 LLM 调用每日上限 + 单用户频控(防刷)
- 打卡上传失败:本地暂存,网络恢复后重传

## 8. 合规与发布

- **主体**:个人主体注册(免费),服务类目建议「工具 > 信息查询」或「生活服务 > 综合生活信息」
- **ICP 备案**:注册当天即在小程序后台提交(免费,1-2 周),与开发并行,不阻塞发布
- **内容安全**:用户上传照片发布前过云开发内容安全检测(`imgSecCheck`)
- **AI 生成内容标注**:推荐理由、ai_comment 界面标注「由 AI 生成」;若审核对实时生成有异议,兜底方案为推荐理由离线预生成进菜谱库
- **隐私**:小程序隐私协议(照片/相册权限说明)、用户协议
- 名称候选:「开火日记」(首选)/「三餐日记」/「小灶日记」,注册时查重
